# КРОК 3 — АРХІТЕКТУРА ТА ПОТІК ДАНИХ
1. **Імпорт:** `LibraryScreen` → `importBook()` → парсери пишуть глави в `books.db`
   (expo-sqlite). Файл читається ОДИН раз (parse-once).
2. **Читання:** `ReaderScreen` → `getReaderSentences(bookId, dbVersion)`
   (`services/readerSentences.ts`) → глави з БД → `stripHtmlToText` →
   `splitIntoSegments` → одне речення = один елемент. Плюс bounded-кеш на перевідкриття.
3. **Сегментація:** ОДНЕ речення = ОДНА секція (без групування в абзаци). Розбиття —
   тільки по термінальній пунктуації + велика літера/цифра; довге речення (>200 симв)
   ріжеться додатково по `:` і `;` (хвіст ≥40 симв, мала літера).
4. **Переклад:** per-sentence. `translationService.ts` (v1 Google GTX, безключовий) —
   основний. `translationServiceV2.ts` (Lingva + фолбек на v1) — для prefetch.
   Ключ перекладу: `paragraphIndex*1000 + sentenceIndex`.
5. **Збереження перекладів:** `sentence_translations` у `books.db` (SQLite), НЕ в
   AsyncStorage JSON. Таблиця має складений ключ `(book_id, skey, lang)`.
6. **Навчальний двигун:** синтез, НЕ клон Anki — власний FSRS, плюс імпорт/експорт
   `.apkg` для сумісності. Користувач **видаляє** знайомі слова (не підтверджує).
   Режим True/False — ідея користувача.
7. **Монетизація:** AdMob (банер + rewarded) + донат через NOWPayments. Реальні
   prod ID живуть в `.env` і `eas.json`.
8. **Тренування:** 4 режими. Cloze direction-aware (fwd = EN слово, rev = UA переклад),
   перемикач мови ТІЛЬКИ всередині вправи.

# КРОК 4 — ІНВАРІАНТИ (ЗЛАМАЄШ = ВТРАЧАЄШ ДАНІ)
1. **`sentences[].index` = `paragraphIndex * 1000 + sentenceIndex`.** Це ключ `skey` у
   таблиці `sentence_translations`. Зміна формули = втрата ВСІХ збережених перекладів.
   Будь-який рефакторинг пайплайна речень мусить зберегти формулу точно.
2. **`paragraphIndex` на DB-шляху = `chapterIdx * 1000 + si`.** Далі воно множиться на
   1000 — тому `chapterIdx` не має перевищувати ~900 для розумних індексів.
3. **Legacy-шлях** (`libraryStore.paragraphs`, один paragraph = ціла ГЛАВА) потребує
   СПРАВЖНЬОГО розбиття. Не оптимізуй його "в нуль" — там `splitIntoSegments` обов'язковий.
4. **Hermes НЕ підтримує `import.meta.url`** → Web Worker через `new Worker(new URL(...))`
   неможливий. Варіант з inline Blob-Worker теж не працює (немає доступу до парсерів через
   `require()`). Парсери працюють на main thread з yield через
   `await new Promise(r => setTimeout(r, 0))`.
5. **RTF:** `\'hh` використовує Windows-1252 (НЕ Unicode). Потрібен мапінг WIN1252_MAP
   для байтів 0x80–0x9F. Після `\uN` треба пропускати fallback-символ. Парси БАЙТИ, не
   UTF-8 рядок — `TextDecoder('utf-8')` перетворює 0x93/0x94 на U+FFFD.
6. **Тіні на Android:** `boxShadow` з `inset` РЕНДЕРИТЬСЯ (це не баг). Внутрішні тіні =
   м'який inset з blur>0. "Біла полоска" = inset з blur=0 → м'якшити до blur 3, НЕ
   видаляти. "Обводка" = `borderWidth:1` → прибирати border повністю.
7. **Обидві теми — завжди.** Після зміни тіней/теми перевіряти Day І Blackout/FLAT.
   Проблема зникнення внутрішніх тіней у світлій темі повторювалася вже 4 рази —
   користувач ЗЛИТИЙ на її регресію.
8. **`blackout` = FLAT** (ThemePalette.flat), без неоморфізму, без прозорості:
   surface-фон + обводка кольору тексту.
9. **Dev build для тестування, release — тільки після підтвердження.**
